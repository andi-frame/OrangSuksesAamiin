# Problem 2 — Concurrency, availability, graceful degradation (Orang 2)

## Ringkasan

Client-Facing API melayani read **BMKG-only** tanpa terblokir poll PVMBG yang lambat (p95 &lt; 300 ms lewat port **8080**). Saat PVMBG outage, data vulkanik terakhir tetap dilayani dengan **`stale: true`** dan **`freshness.PVMBG.stale_since`**. Rate limit mengembalikan **429** di bawah beban tinggi (diperbolehkan spesifikasi).

Sisi ingest (loop terpisah, breaker): Orang 1 — `make demo-p2-aggregator`.

## Desain

- Read path: client → Aggregator `/internal/*` (bukan database / mock langsung).
- Penanda usang: field `stale` per item + objek `freshness` dari Aggregator.
- Rate limit: `CLIENT_RATE_LIMIT_RPS` / `CLIENT_RATE_LIMIT_BURST`.

## Bukti

| Skenario | Perintah | Artefak |
|----------|----------|---------|
| Ingest / breaker | `make demo-p2-aggregator` | `docs/evidence/p2/aggregator-latest.log` |
| Client p95, outage, k6 | `make demo-p2` | `docs/evidence/p2/latest.log`, `k6.log`, `k6-summary.json` |
