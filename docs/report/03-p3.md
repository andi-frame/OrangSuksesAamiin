# Problem 3 — Authentication & trust (Orang 2)

## Ringkasan

Auth Service menerbitkan JWT HS256 per role (`media`, `lapangan`, `pusat`) dengan access TTL pendek dan refresh token opaque (SQLite). Client-Facing API memvalidasi Bearer, membedakan **401** (tanpa kredensial) dan **403** (token invalid atau hak field/endpoint), serta menegakkan klasifikasi **Ringkasan** vs **Mentah**.

## Mekanisme

| Role | Hazard list/get | `/v1/sources/status` | Field Mentah |
|---|---|---|---|
| Media | Ringkasan + `stale` | 403 | Ditolak; `fields`/`include=mentah` → 403 |
| Lapangan | Penuh + `stale` | 200 | Diizinkan |
| Pusat | Penuh + `stale` | 200 | Diizinkan |

Refresh: `POST /v1/refresh` menerbitkan pasangan token baru; refresh lama di-rotate (one-time).

Isolasi kredensial instansi BMKG/PVMBG: mock Orang 1, bukti `make demo-mock-auth`.

## Bukti

| Skenario | Perintah | Artefak |

Checklist: tanpa Bearer → 401; JWT invalid → 403; Media tanpa Mentah; `?fields=` / `include=mentah` → 403; Lapangan/Pusat + `/v1/sources/status`; access expired → refresh; refresh lama ditolak.
