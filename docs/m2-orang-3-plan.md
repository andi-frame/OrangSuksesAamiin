## 1. Prove the storage topology before building the router

The current deployment has one `postgres-canonical` StatefulSet replica. The recorded demo has two VMs. With two complete copies of every shard on distinct nodes, **both nodes would contain every record**. More pods on those VMs cannot satisfy P1.1. The proposed layout needs three distinct k3s node disks. The existing script accepts `VBOX_NODES="node-a node-b node-c"`. Check allocatable RAM for the whole stack, including Orang 2's workloads. If the third node cannot be provisioned, record P1.1 as blocked for this design and continue the adapter and feed tests.

| Logical shard | Initial primary | Synchronous standby |
|---|---|---|
| S0 | node-a | node-b |
| S1 | node-b | node-c |
| S2 | node-c | node-a |

- Route by a specified, versioned hash of the stable hazard ID into three fixed logical shards. Record the hash and test vectors. Use a ConfigMap for membership. Replacing a node moves a physical copy without changing a hazard's logical shard. Compare this choice against region-based partitions and time-range partitions using the same catalog and regional burst.
- Reuse PostgreSQL transactions and physical WAL replication. Prototype Patroni per shard using Kubernetes coordination, a primary Service and mandatory hostname anti-affinity within each shard. Give Patroni its own role-label key so all storage pods retain the Tester's `role=store`. Record the actual node and role after each promotion. [Patroni on Kubernetes](https://patroni.readthedocs.io/en/latest/kubernetes.html)
- Document and test the write policy. In healthy operation, acknowledge writes after the cross-node standby confirms them. During loss of a copy, promote only an eligible synchronized standby, allow its authoritative primary to make progress with one copy, and never promote a stale or isolated copy. This trades protection against a *second* loss during repair for write availability. Restore two verified copies before declaring recovery. Exercise partition, freeze/thaw and ambiguous commit retries before accepting this policy. [Patroni synchronous replication modes](https://patroni.readthedocs.io/en/latest/replication_modes.html)
- Extend `deploy/k8s/`, `deploy/kustomization.yaml`, `scripts/k8s/{up,images,secrets}.sh`, Compose and `.env.example`. Each storage instance uses a local PV/hostPath and 512Mi request / 1Gi limit. Limit application access to the Aggregator, allow scoped replication between shard peers, and keep Tester Agent access intact. Register any new component's Dockerfile, image, role, health check, resources and Secret. New Kafka clients need `bnpb.io/kafka-client: "true"`.

## 2. Implement the repository and recovery path

1. Add a backend under `services/aggregator/internal/adapters/`, register it and import it in `cmd/aggregator/backends.go`. Reuse the existing PostgreSQL adapter per shard. Keep `Save`'s hazard, version check and outbox row together. Route each hazard's outbox acknowledgement to its owning shard. Merge pending work fairly so a busy shard cannot starve another.
2. Place shared cursors, source status, DLQ and satellite checkpoints on a designated replicated metadata shard. Preserve DLQ sequence ordering, exact raw payloads and requeue semantics. When migrating an existing database, route hazards and outbox rows together, preserve versions, published flags, fences and watermarks, and reconcile source counts/checksums before switching reads and enabling the new writer.
3. Run the existing PostgreSQL fence check **inside each mutation transaction**, including satellite mutations. Replicate that transaction, including its fence row, to each standby. `RaiseFence` must cover every logical shard and all its eligible copies before admitting a new leader. An unreachable former member must be excluded from service and promotion until it has replayed the current term and caught up. Never count a timed-out unit as successfully fenced. Demonstrate that an old writer cannot commit a hazard, cursor, checkpoint or outbox entry after a new term is admitted.
4. Fan out reads with bounded deadlines, choose one authoritative copy per shard, fetch one extra item and merge by the endpoint's full sort key. Add coverage metadata through `ports.Page`, the Aggregator response and the client-facing read path. Keep storage coverage separate from upstream freshness. `/ready` succeeds while at least one shard can serve reads. Return explicit partial results and unit names on an outage. A point lookup can assert absence only when the responsible shard was checked. Document how to restart a partial scan after recovery to capture skipped rows.
5. Automate replacement on a new or emptied worker. Seed missing copies from the survivor, stream writes made during the copy, verify replay position and fence, and admit the replacement. Move a primary role to the replacement so it receives writes as well as data. Exercise a second worker loss after redundancy has been restored. Keep issuing reads and writes during rejoin and retain their outcomes.
6. Run `internal/ports/repotest.Run` against the real multi-unit backend, including `runFence`. Add regressions for cross-shard cursor ties, a lost commit acknowledgement and retry, partial readiness, stale replica rejoin, and a stale term on **each** shard after promotion. Keep memory and single-PostgreSQL tests passing. Adapt `scripts/demo/k8s-lib.sh` and the P2 SQL assertions with Orang 1. They currently query only `postgres-canonical-0`. Count each logical record once and compare writer periods on the same database clock per shard.

Extend the repository's read capabilities and its test adapters. Publish the wire contract in `docs/contracts.md` and `contracts/openapi/aggregator-internal.yaml`.

| Route under `/internal/audit/` | Required behavior and acceptance test |
|---|---|
| `events` | All fields of each active HazardEvent. Optional `source` and inclusive `since` on **ingested_at**. Sort by `(ingested_at, hazard_id)` ascending, default limit 100, maximum 1000, opaque cursor, JSON null at end. Page through tied timestamps on different shards and compare with an independently sorted list. Keep the ordinary newest-first hazard endpoint's existing cursor semantics. |
| `checksum` | Optional `source`, otherwise all sources. From one logical copy of each active event, sort its `source_ref_id` by bytes, join with LF and no trailing LF, and return lowercase SHA-256, count, source, algorithm and UTC `as_of`. | `location` | Require `hazard_id`. Return verified storage unit names, actual Kubernetes node names, and current `primary`/`replica` roles. Test missing parameter (400), confirmed absence (404), a known event before/after promotion, and uncertain location while a unit is down. |

Test all three with missing/invalid bearer (401), another principal's bearer (403), JSON error envelopes and UTC timestamps. Verify invalid dates/cursors and limit handling. During unit loss, name unreachable units and set `partial: true` as Appendix A requires, even when a surviving copy supplies all rows. Report full logical row coverage separately in the evidence. On a healthy scan, emit `partial: false` and empty unit lists where specified. Give Orang 2 a healthy and a degraded sample plus expected counts per hazard type, severity and area for the dashboard comparison.

## 4. Build P4 as a leader-owned SSE consumer

1. **Capture the feed contract.** Start with authenticated `GET /v1/session` and a bounded practice `GET /v1/stream?from=<offset>`. Inspect SSE IDs, multiline data, heartbeat, update/retract references and resume inclusivity. Redact credentials. Mount the existing `satellite-feed-credentials` through `secretRef` on the Aggregator. Add the consumer to the elected ingest lifecycle in `cmd/aggregator/main.go`, gated before connection and cancelled on leadership loss. Bound buffers and reconnect with backoff/jitter for disconnects, 429 and 503. Surface 400/401 as actionable configuration errors.
2. **Persist before advancing.** Add a satellite inbox keyed by feed session/identity and offset, plus a processed-offset checkpoint distinct from the timestamp polling cursor. Preserve the exact tokens in `satellite|acq_date|acq_time|latitude|longitude`, including leading/trailing zeroes. Decode time and coordinates separately for computation. Resume from the durable contiguous position, tolerate a repeated boundary event and request replay on a gap. Advance past a heartbeat only according to its observed offset semantics.
3. **Group by event time.** Use UTC acquisition date/time, exclude low confidence, and deduplicate on the five-field key. Connect detections at distance ≤1 km **and** time difference ≤360 minutes. Use a spatial/time index for candidate neighbors and an exact distance check. Form transitive components across satellites. Count singletons separately. On a correction or retraction recompute the affected neighborhood, including splits and merges. Use a configurable allowed-lateness interval, measure it on practice input and document the chosen value. Use an event-time watermark, count/persist details of over-late detections, and retain membership needed for explicit corrections after window closure.
4. **Materialize canonical fires.** For components of size ≥2 emit `SATELIT/WILDFIRE`, earliest detection time, centroid, nearest province center from a versioned static BNPB table, detection count, sorted unique satellites, highest confidence, total FRP in MW, and sorted raw detection keys. AWAS starts at 20 detections **or** 100 MW. SIAGA starts at 6 **or** 30 MW. Otherwise use WASPADA. Extend `domain.HazardID`, API filter validation and both hazard/envelope JSON schemas. The existing default ID prefix is `pvmbg-`. Coordinate shared COASTAL/SENSOR_PANTAI enums with Orang 2.
5. **Preserve identity and recover across shards.** Persist a fire's ID when a component first qualifies, derived from a deterministic formation key and ordered feed history. Keep it on ordinary updates and when its original detection is withdrawn. Define deterministic survivor rules for merges/splits. Retire disappeared IDs via a versioned tombstone, exclude them from all active reads/checksums and notify downstream consumers. Agree the envelope change with consumer owners. In one fenced metadata transaction commit membership, planned versioned mutations and the processed offset. Apply those mutations to owning shards in recorded order, each with an idempotency key and a local atomic hazard/outbox transaction. Replay unfinished mutations after restart. Track ingestion completion through the **applied** offset, so an inbox checkpoint cannot conceal pending work. Handle ID revival without resetting its version.
6. **Measure correctness and lag.** Replay fixtures for verbatim keys, multisatellite chains, exact thresholds, low confidence, isolated detections, late bridges, corrections, retractions, splits and ID retirement. Interrupt after inbox commit, during clustering and between hazard writes. Compare resumed and uninterrupted logical results, versions and outbox keys. Export feed head, applied offset, lag, late/singleton counts and receive-to-durable-hazard latency for Orang 2. At 60× capture peak lag, p95 latency and elapsed time from burst end to catch-up (≤60 s). Compare the complete fire membership and fields with the assistant reference and explain differences. Record several minutes of the live feed and a disconnect/reconnect with contiguous offsets.
